# 喵呜庭院 v2.1 · 本地互动游戏

这是根据《喵呜庭院》方案实现的完整本地可玩项目，包含源码、全部图片与音效、测试、素材索引。可以在 **Trae** 打开，执行后直接交互。无需 API Key、账号或在线图片服务。

v2.1 优化订单引导、手机合成布局和猫咪动作预览。棋盘上方可查看三份订单的材料进度，点击目标定位物品和菜篮子；“找合成”给出下一步建议，凑齐材料可直接交付。猫咪档案增加暂停、下一帧和倍速播放，已有480帧动作素材全部保留。使用方法见 [v2.1更新说明](docs/v2.1更新说明.md)。

## 在 Trae 中运行

**最快方式，无需安装Node：** Trae打开项目文件夹后，在Windows终端输入 `start .\index.html`，直接打开浏览器游玩。也可以在资源管理器双击 `index.html`。

**本地开发服务器方式：**

1. 解压整个压缩包，保留目录结构。
2. Trae → 打开文件夹 → 选择 `MeowCourtyard`（其中应有 `package.json`）。
3. 电脑安装 Node.js 18 或更高版本后，在 Trae 终端执行：

```bash
npm run dev
```

4. 打开终端显示的 `http://localhost:5173`。

**本项目没有第三方运行依赖，不需要执行 npm install。** 修改 JS/CSS/HTML 后保存并刷新浏览器即可看到效果。

Windows 也可以双击 `start.bat` 启动，服务就绪后才会自动打开浏览器；游玩时请保留启动窗口。没有 Node.js 时，直接双击 `index.html` 或 `play-offline.bat` 也能游玩。推荐使用 Trae + 本地服务器，存档来源更稳定。

如果提示“无法访问此站点”，请先运行 `start.bat`，或在项目目录执行 `npm run dev`，看到启动成功后再访问网址。若只想立即离线游玩，双击 `play-offline.bat` 即可，无需服务器。离线文件入口与 `http://localhost:5173` 使用不同的存档位置，原网页存档不会被删除；要转移进度，请在原入口的设置中导出，再到新入口导入。

如果出现“npm无法识别”，可以使用上述直接打开方式；或安装带npm的Node.js后重启Trae。仅有node命令时，可用 `node server.cjs` 启动同一服务器。

端口占用时在 PowerShell 执行：

```powershell
$env:PORT=5180
npm run dev
```

然后访问 `http://localhost:5180`。不同端口的浏览器存档相互独立。

## 一分钟上手

- **进入庭院**：两只初始猫咪已入住，点击小猫出现呼噜动画、爱心和呼噜音效。
- **合成小铺**：开始关卡消耗5体力。点5种菜篮子，基础物品弹入可用空格，每次消耗1生成点和1步。把两个同系列同等级物品拖到一起升级，也支持双点与触屏操作。
- **永久解冻**：新庭院有12个冰格。在冰格上下左右完成合成即可融化相邻冰格。单纯移动不解冻，已融化的格子换关、刷新或重新进入都不会再结冰。
- **每日领取**：页面顶部可分别领取10点登录体力（上限30）和300购物金币，每项每天一次，北京时间零点刷新。体力满时不占用领取机会；接近上限时按剩余容量到账。
- **订单**：棋盘上方查看三单进度，点击订单定位物品及对应菜篮。凑齐后可在顶部直接交付，也可在愿望清单点“交付小礼物”。每关3单，获得金币、星星和体力；完成后继续下一关。
- **合成引导**：“找合成”只高亮建议，不自动操作、不扣资源。“相邻连合”会保留已凑齐订单的材料，包括连合过程中刚刚凑齐的材料。
- **养猫**：在图鉴领养、召唤和收纳小猫。庭院中可喂饭、散步、睡觉、晒太阳；猫咪档案中可逗猫。
- **建设**：商店扩建猫位，星星布置装饰，等级与资源达到要求后解锁新地图。
- **满棋盘**：先合成或交付。也可选中物品回收，商店提供整理、升级和步数补给。

## 立即体验所有内容

**设置 → 进入素材试玩**：开放30只猫咪、4张庭院和充足资源。各地图分配了猫咪，切换地图即可检查动作。

此模式只存在于当前页面内存，**不覆盖正式存档**。点击顶部“返回正式存档”恢复进度，刷新页面也会恢复正式存档。正式模式仍按金币、等级、猫位规则游玩。

## 交付内容

| 资源 | 数量与规格 |
|---|---|
| 进入画面 | 1张，1536×1024 PNG |
| 庭院场景 | 4张，1536×1024 PNG |
| 猫咪动作 | 30品种 × 6张 = **180张透明PNG**，256×256 |
| 猫咪连续动作 | **30套 × 16帧 = 480帧**，每套1024×1024透明PNG，4×4排布，另附时序JSON |
| 旧版猫咪动作条 | 每品种1张，6帧横排，保留作为素材档案 |
| 菜篮子 | 1张256×256透明PNG，界面叠加5类物品并播放弹出动画 |
| 合成物品 | 5条链 × 6级 = **30张透明PNG**，256×256 |
| 原始生成图集 | 保留分组源图与修正素材 |
| 音效 | 呼噜、合成、奖励，3个本地WAV |
| 界面截图 | 进入、庭院、合成、结算、图鉴、地图及手机布局 |

每种猫咪使用独立的 **8帧行走与8帧进食** 图集。行走约8.7帧/秒，并按移动方向翻转；进食按准备、低头、啃咬、咀嚼、吞咽、抬头的时序循环。睡觉、呼噜、晒太阳保留原姿态和轻动效。图鉴档案可切换“散步”/“吃饭”，暂停、逐帧查看，并选择0.5、1、1.5或2倍速度。图集尚未载入时显示静态姿态；离屏、后台或系统开启“减少动态效果”时暂停自动播放，手动逐帧仍可使用。

五条升级链为猫薄荷、猫爪大福、铃铛、小鱼干、小鸟玩具。升级名称见游戏内“物品图鉴”与 `src/data.js`。

## 常用命令

```bash
npm run dev    # 启动本地游戏
npm test       # 规则与素材完整性测试
npm run build # 生成 dist 静态发布目录
```

`dist` 可直接打开或部署到静态服务器。构建只复制本地资源，没有下载过程。

v2.1 已通过66项单元测试和11组专项浏览器检查。合成页在320、360、390、650、768、850和1024像素宽度下无横向溢出；390×844手机首屏可同时看到订单目标、完整棋盘和五个菜篮子。验证记录见 [验收说明](docs/验收说明.md)。

## 存档与声音

进度每10秒以及关键操作后写入 `localStorage`，关卡中途退出可继续。设置可导出/导入JSON备份。更换浏览器、端口或移动目录前请导出备份。浏览器隐私模式或禁用存储时，建议主动导出。

v2.1继续使用原来的存档位置和v2存档格式，并自动兼容v1存档。v2进度可直接续玩；迁移v1时保留棋盘和资源，冰格视为已解锁，已有的当日礼包领取记录会迁移，避免重复领取。要体验初始冰格，可使用“设置 → 素材试玩”进入合成小铺，无需删除正式存档。

音效在点击交互后播放；设置可关闭。呼噜声为程序合成的低频效果音，不是真猫录音。

## 实现范围

这是**可交互的单机网页版**，交付完整客户端项目。实现了核心合成与庭院养成循环、30猫、4地图、商店、资源、关卡、自然体力恢复、离线金币、本地存档与素材试玩。

原方案的商业后端（账号云存档、服务端反作弊、支付广告、好友、排行榜、数据仓库）尚未接入；本地经济数据可被用户修改。也不包含 Cocos Creator 原生工程或安卓APK。具体数值调整与方案差异见 `docs/实现对照.md`。

玩法参考为“菜篮子生成→二合一→完成订单→建设”的结构；未复制《浪漫餐厅》的图片、角色、文案或代码。全部美术由内置 image_gen 生成，初版提示词在 `docs/生成提示词.json`，v2图集与篮子的提示词在 `docs/v2生成提示词.json`。v2.1沿用这些素材；冰格和每日奖励规则见 `docs/v2更新说明.md`，本次操作改进见 `docs/v2.1更新说明.md`。
